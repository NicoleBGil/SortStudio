09 / QUANTIFY THE CHAOS
Disorder has a number.
An inversion is a pair of positions whose values are in the wrong relative order. Each lit cell below represents one inversion in the current starting array. Edit the array in the playground to change this view.
Why does this explain Bubble Sort?
Swapping adjacent, out-of-order values removes exactly one inversion. Therefore the number of Bubble swaps equals the initial inversion count. Insertion's right shifts equal the same count; its final key writes add n−1 writes. Selection can remove several inversions in a single distant swap.


10 / LOOK BEYOND THE NUMBERS
Equal values. Different identities.
If records have equal keys, do they keep their original order? Imagine students sorted by score: an earlier name may need to stay earlier. Follow A and B, which share the same key.
Controlled counterexample: [20A, 20B, 10C]. The supplied strict-comparison Bubble and Insertion implementations preserve equal-key order. Standard swap-based Selection may reverse it. One example illustrates behavior; it is not a general proof.


THE FINDINGS
There is no single
“best” journey.
01
Structure changes the work.
For 20 already sorted values, Bubble and Insertion perform 19 comparisons. Selection still performs 190.
02
Your metric changes the winner.
For [3,2,1], all three make 3 comparisons. Selection uses 2 array writes, Insertion 5, and Bubble 6.
03
Correct order is only one goal.
Stability, movement cost, and existing order can all matter. These small-scale operation counts do not measure wall-clock performance.

MODEL / EVIDENCE / ATTRIBUTION
◎ Scientific Notes
Question: How do three classical sorting algorithms differ in their comparison patterns, movement counts, and response to input order?
Method: The application executes deterministic algorithm implementations and records snapshots after comparisons and modifications. The battle advances one recorded event per tick; the event count is a visualization-specific metric, not a benchmark of CPU execution time.
Measurement: One comparison is one value-ordering check. Bubble and Selection count swaps; Insertion counts writes to array positions. Swaps and writes are different units and should not be interpreted as directly comparable hardware costs. Heatmap cells describe array-position pairs, not fixed value identities.
Reproducibility: The lab uses a fixed-seed shuffled array for its random scenario. The interactive arena can use newly generated random arrays.
Limitations: Different implementations may have different counts. Algorithm animations illustrate behavior; no real-time CPU or memory profiling is performed.

Model, schema, workflow, and numerical verification
Workflow: input controls → generated or validated integer array → deterministic sorting functions → immutable event snapshots → charts, counts, and downloadable JSON. There is no external dataset or missing-value imputation. Invalid custom values are rejected.
Schema: a = array state; c = cumulative value comparisons; m = swaps (Bubble/Selection) or array writes (Insertion); phase = event type; active = highlighted zero-based positions; pairs = compared positions; key = held insertion value, when applicable. Values and positions are dimensionless.
Equations: Selection performs n(n−1)/2 value comparisons. Sorted input takes max(0,n−1) comparisons for early-exit Bubble and Insertion. One swap writes two array cells, so common array writes = 2m for Bubble/Selection and m for Insertion. Local-variable writes and loop checks are excluded. Events include a completion marker and candidate changes, so event totals depend on instrumentation.
Insertion caveat: the key is held outside the array during shifts. Temporary duplicates in array cells are expected; the held key is displayed in the event message. Heatmap pairs mark the scanned cell and the next insertion slot, not two resident values.
Design: zero-baseline bars encode values, a matrix reveals position locality, experiment bars compare counts, direct array editing explores order, pseudocode links operations to implementation, prediction feedback tests understanding, lines reveal scaling, and cumulative traces connect mechanism to cost. Amber and explicit position labels identify active cells.
Related work: VisuAlgo provides algorithm animation; this project adds controlled hypotheses, position heatmaps, and reproducible operation-count comparisons. These sources are reference links; the implementation measures its own simulated operations.
